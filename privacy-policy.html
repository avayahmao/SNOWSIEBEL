Privacy Policy for SNOW + Siebel Ticket Manager

Last updated: June 27, 2026

Overview

SNOW + Siebel Ticket Manager is a Chrome browser extension that provides a sidebar interface for managing ServiceNow tickets and Siebel CRM activities. This privacy policy describes in full how the extension collects, processes, stores, and shares user data.

Short version: This extension does not collect, sell, share, or transmit any personal data to the developer or any third party. It only displays data that already belongs to the user's own organization (Avaya), retrieved live from the organization's own servers using the user's own browser session, and it is never persisted outside the browser. The details below satisfy the Chrome Web Store requirement to disclose each of these points explicitly.

1. Data Collection

The extension does not collect any personal or sensitive user data. No analytics, telemetry, crash reporting, or usage tracking is present. The only data the extension touches is data that already exists in the user's organization-owned systems (ServiceNow tickets, Siebel activities), and it is read on demand only when the user performs an action in the sidebar.

For completeness, the data the extension displays or submits (always at the user's explicit request) is:

  • ServiceNow ticket data — ticket numbers, descriptions, state, priority, assignment, journal (work notes/comments), and CI remote-access info (IP addresses, SE IDs, device credentials) for tickets the user opens or searches.
  • Siebel CRM data — Service Request / Activity numbers used to open or create activities in Siebel.
  • OCD API data — the user's open Siebel backlog (SRs/SRAs) for sidebar display.
  • Local preferences — the List-tab sort selection (key + direction), stored in the browser's localStorage. No ticket data is stored.

2. How Data Is Used (Processing)

All processing happens locally, inside the user's browser:

  • The sidebar UI (panel.js) renders ticket/backlog data to the screen and builds the forms the user submits.
  • The service worker (background.js) routes user actions and injects helpers into the already-open ServiceNow / Siebel tabs.
  • The injected helpers (content-snow.js, content-gct.js) read the page's existing session token (g_ck) and cookies to call the organization's REST/JS APIs — exactly as the user could do manually in those tabs.
  • Journal (work notes/comments) and markdown-export content is parsed in the browser from data already returned by the organization's API; no external parsing or AI processing occurs.

No data is processed on any developer-controlled server. There is no developer backend.

3. Data Storage

  • Nothing is written to external databases, clouds, analytics, or third-party servers. The developer operates no server that receives extension data.
  • Browser-local storage — only the List-tab sort preference is saved (in localStorage, scoped to the extension). It contains no personal or ticket data.
  • No persistent storage of ticket data — all ticket/backlog/credential data shown in the UI is fetched fresh on each action and held only in memory for the duration of the view. It is discarded when the sidebar closes or reloads.
  • Device credentials (IP, SE ID, passwords) shown on ticket cards are fetched on demand and never written to disk.

4. Data Sharing

The extension does not share data with any third party. Specifically:

  • It does not transmit data to the developer or any developer-owned service.
  • It does not use advertising, analytics, or tracking SDKs.
  • It does not sell, rent, or barter data.

The only data movement is between the user's browser and the user's own organization's servers, over the user's existing authenticated sessions — the same endpoints the user visits directly:

  • ServiceNow (avaya.service-now.com) — read ticket lists/details/journal; submit work notes, status updates, and alarm closures.
  • Siebel CRM (gct.avaya.com) — create activity records on Service Requests via the Siebel JavaScript API.
  • OCD API (ocd.avaya.com) — fetch the user's Siebel backlog for sidebar display.

These are first-party (organization-owned) endpoints, not third parties. No data leaves the Avaya corporate environment.

5. Authentication

All communication uses the user's existing browser SSO sessions. The extension does not collect, prompt for, or store any credentials, passwords, or API tokens. The ServiceNow g_ck CSRF token is read live from the page context at call time and never persisted or transmitted anywhere except back to ServiceNow as the required request header.

Permissions

  • activeTab — Used to access the currently active ServiceNow or Siebel CRM tab when the user performs an action from the sidebar.
  • scripting — Used to inject content scripts into ServiceNow and Siebel CRM pages to access the page's CSRF token (g_ck) and Siebel JavaScript API for authenticated operations.
  • sidePanel — Used to display the extension's user interface as a browser sidebar panel.

Host Permissions

  • avaya.service-now.com — Required to inject scripts and make REST API calls to the ServiceNow instance.
  • gct.avaya.com — Required to inject scripts and automate Siebel CRM activity creation.
  • ocd.avaya.com — Required to fetch the user's Siebel backlog data from the OCD API.

Remote Code

This extension does not load or execute any remotely hosted code. All code is bundled within the extension package.

Data Retention & Deletion

Because no data is collected or stored by the extension or developer, there is nothing to retain or delete on the developer's side. The only locally stored item (the sort preference) can be cleared by uninstalling the extension or clearing site data. Ticket data shown in the UI is governed by the organization's own retention policies in ServiceNow/Siebel, not by this extension.

Children's Data

This extension is an enterprise workplace tool and is not directed at children. It does not knowingly collect any data from anyone.

User Rights

Since the extension collects no personal data and shares nothing with third parties, the usual access/rectification/erasure rights are satisfied by design: no personal data about the user exists outside the organization's own systems, where it is governed by the organization's policies. The sort preference can be cleared at any time.

Changes to This Policy

This privacy policy may be updated if the extension's functionality changes. Any updates will be reflected on this page with a revised "Last updated" date.
